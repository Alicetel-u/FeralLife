# 音声チェックのGitHub同期

判定データは非公開の `Alicetel-u/FeralLife-voice-review` リポジトリの `voice-review.json` に保存する。ゲーム本体・一般プレイヤーのセーブ・ElevenLabsのキーは保存しない。

## 使い方

1. 記録があるPCで音声チェックを開き、右上の「GitHub同期」→「GitHubへ保存」を押す。
2. 別PCで「GitHub同期」→「GitHubから読み込む」を押す。
3. 続きの作業を終えたら「GitHubへ保存」を押す。

最初の保存先は空。別PCのブラウザーにある既存の判定を、ゲームソースや画像だけから復元することはできないため、まず記録のあるPCから保存する。自動同期ではなく明示的な保存・読み込みを行う。

## ローカル版

このプロジェクトで `npm run dev` を実行して開く。GitHub CLIの `gh auth login` で Alicetel-u にログインしておけば、トークンの入力なしで同期できる。別PCでも同じアカウントへログインする。

ローカル同期APIは `127.0.0.1` にのみ接続待ちする。独自ヘッダー、Host、Originを検証し、外部サイトからの呼び出しを拒否する。GitHub操作は固定の同期先ファイルに限定し、認証はCLI側で処理する。認証トークンはブラウザーへ返さない。

## 公開版・play.html

GitHub同期画面で Fine-grained personal access token を入力する。Resource owner は Alicetel-u、Repository access は Only select repositories で `FeralLife-voice-review` のみを選び、Contents を Read and write にする。

入力したトークンは音声チェックを閉じるまでのメモリー内だけで扱う。localStorage、バックアップ、リポジトリ、公開ビルドには保存しない。再度音声チェックを開くと入力が必要。公開版は入力した認証で `api.github.com` と直接通信する。

## 統合と失敗時

- 保存前にGitHubの最新データを読み、台詞ごとの `updatedAt` が新しい判定を優先する。
- 同時刻の競合は決定的なルールで統一し、指摘を優先する。異なる音声版の旧指摘は履歴にも残す。
- 同時保存でSHAが競合した場合は最新データから統合し直し、最大3回まで試みる。
- 非公開でないリポジトリには保存も読み込みもしない。
- 通信・認証・データ検証に失敗しても端末の記録は消さない。
- 同期で取得した確認済み・指摘済みは未確認一覧から外れ、差し替え後の音声は修正後の確認に分かれる。
- 端末の音声チェック用の絞り込みやカーソルを、別PCの設定で上書きしない。
