# 音声チェックの出力・本番反映

## 利用者の流れ

1. デバッグメニューの音声チェックを開く。通常画面は未判定の音声だけを表示する。
2. 気になる点を付けるか「問題なし」を押す。問題なしは直ちに一覧から外れる。
3. 「指摘を出力」から全文をコピーしてCodexに渡す。問題なしの判定も、末尾の取り込み用データに含まれる。指摘がゼロでも出力できる。
4. Codexが出力を取り込み、指定の音声を修正してビルド・テスト・GitHubへのpushを行う。
5. 本番ページを再読み込みすると、別PC・スマホでも公開された判定が適用される。修正された音声は「修正後の確認」ボタンから試聴する。未確認一覧には混ぜない。
6. 修正後に「問題なし」とした判定も、次の出力・公開で全端末に反映する。

GitHubのログイン・トークン入力・判定用の別リポジトリは不要。公開前の作業記録は端末内に自動保存される。端末で判定を付けただけでは、ほかの端末へ即時反映されない。

## 修正・公開する側の手順

出力全文または従来のバックアップJSONを、Git管理外の `.local/` に保存する。生の依頼・個別メモはコミットしない。

```powershell
node tools/publish-voice-review.mjs .local/voice-review-report.txt
```

これで `config/voice-review-published.json` の共通判定を更新する。問題なしと要修正を取り込み、未判定・単なる再生済みは公開判定にしない。公開する情報は台詞の識別キー、OK/NG、音声の内容ハッシュ、判定日時だけ。個別メモ・指摘の詳細・認証情報は含めない。

既存の手順で対象音声だけを修正し、マニフェストに `repairReview: true` と事実に沿った `repairComment` を設定する。`npm run build` がカタログと公開判定モジュールを生成する。テスト後、判定設定・生成モジュール・修正音声・マニフェストをまとめてmainへpushし、Pagesの公開成功を確認する。

同じ音声への新しい端末内判定は維持する。古い音声版への指摘は、日時が新しくても現行音声のOKを上書きしない。以前のローカルメモは履歴に残す。通常のゲームセーブには書き込まない。

まだ出力されていない別PC・スマホ内の判定は、コードから復元できない。最初の共通判定は空で、既存の修正対象はマニフェストの修正情報によって修正後の確認へ表示される。

## スマホから渡す場合

「指摘を出力」→「ファイルで共有」でテキストファイルを共有する。共有先として使えるチャットアプリは端末によって異なる。ファイル共有に非対応の場合は自動で保存する。「ファイル保存」も使える。スマホでこのチャットを開いてファイルを添付すれば、KeepやPCのコピー操作を経由する必要はない。

コピーが必要な場合は「短くコピー」を使う。短縮形式は台詞の固定IDを使い、公開済みの判定は再送しない。以前の長い出力やバックアップJSONも引き続き取り込める。全履歴のバックアップは「記録の保存・復元」から保存できる。

「問題なし → 次へ」は、連続モードがOFFでも次の音声をすぐ再生する。OFFの場合はその1本が終わったところで止まる。

音声デバッグ固有の再生経路を直した場合、マニフェストの `reviewRevision` を変えて再確認を要求できる。指紋は音声の実データとこの再生修正識別子を合わせて計算し、通常の録音では従来の指紋を維持する。

音声チェックの再生ボタン上に、音声ファイル全体の再生バーと現在秒数／全体秒数を表示する。末尾の無音も含み、最後まで再生されると「再生終了」になる。次の音声へ移るとバーはリセットされる。

## 現行本編だけを確認する

確認対象は tools/voice-reachability.mjs が実際の選択肢・シナリオ進行・巻き戻しの受け渡しを実行して照合する。ソースに残っていても、現在選べない分岐、旧巻き戻し、表示されない独り言や旧イベントは対象にしない。2026-10-27の整理で80件を除外し、807件から727件へ変更した。共通台詞は残し、出現箇所が廃止分岐になっていたものは現行の場面へ直す。

除外した台詞は未確認・修正後の確認・通常の絞り込み・再生には出さない。端末内の既存判定は削除履歴に残す。除外前の短縮出力を取り込むため、生成カタログのVOICE_REVIEW_RETIREDには旧IDの対応表だけを保持する。音声ファイルとマニフェストは旧セーブ互換のため維持する。修正依頼に除外済みの指摘が含まれていても、レビュー出力からの音声生成ではそれを再生成しない。

到達可能だが録音がない台詞は別の診断として扱う。この整理では追加生成を行わず、現行の録音済み音声だけを確認対象にする。
