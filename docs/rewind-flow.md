# タイムループ後の再挑戦

全幕共通の流れは、BAD → 失敗したトラブルの開始状態へ巻き戻し → 専用会話 → そのトラブルの選択肢。専用会話の後に、相談・事件の登場・ミニゲーム開始会話を再生しない。通常の初回進行は変更しない。

## 新しい幕・トラブルを追加するとき

1. 通常進行で `saveStoryCheckpoint` を使い、未回答のトラブルの開始状態を保存する。解決済みの前の事件を含める。
2. BAD後はその状態を復元し、失敗の記憶・選択履歴を引き継ぐ。時計表示と会話の時間を合わせる。複数ラウンドのミニゲームは1ラウンド目・初期メーターに戻す。
3. `rewindIntroPending=true` と、`rewind` または `actN-rewind` の専用会話イベントを作る。会話には人物の体験と反省を書く。未登場扱いの人物への突然の返答や、ミニゲームの敵の発言を混ぜない。
4. 専用会話の終了時は `resumeStoryRewind(state, openPending)` を呼ぶ。未回答事件がまだなければ、`openPending` で通常のシナリオ関数から作る。第二幕は `resumeActTwoRewind` がそのアダプター。
5. 戻り値のイベントを `eventConversation` の最後の行・最後のページで表示する。`src/app.js` の `data-rewind-resume` が実例。対決の場合は保存カーソルも更新する。

共通関数は会話終了・選択待ちの印を保存し、元の会話ログとチェックポイントを保持する。選択待ち画面では省略した本文と音声を繰り返さない。`event-stage.js` と `styles.css` の `rewind-choice-ready` は、この画面だけ本文を隠し、選択後は既存メッセージウィンドウを使う。

## 確認項目

- 専用会話の最終操作から3択へ直接進み、観察・通常の相談会話・バトル開始説明が挟まらない。
- 初回、再失敗、専用会話途中の保存、選択肢表示後の再開、旧セーブでも同じ事件へ戻る。
- 以前の解決済み事件と失敗の記憶を保持し、時計・対決ラウンド・メーターが一致する。
- スマホの1画面に全選択肢が収まり、選択後は通常の会話・音声・演出が機能する。
- デバッグの「事件冒頭」「巻き戻し会話」「選択肢直前」を実際の処理から構築する。
