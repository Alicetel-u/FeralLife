# ローカル音声生成

## 発声方針（2026-10-26ユーザー指定・過去のASMR方針より優先）

既存・今後追加する全キャラクターで、明瞭で張りのある発声と自然な抑揚を基本にする。通常会話は元気よく。心の声・誘惑・悲しみでも囁き・ぼそぼそ声を標準にしない。感情やキャラクター性は保ち、悲劇を明るく演じさせない。生成入力では小声・囁きタグを拒否する。設定変更だけでは既存録音は変わらず、一括再生成は行っていない。

今回の第一幕5件は対象を限定して再生成し、音量を整え、語尾を削らず末尾に0.20秒の余白を付加した。デコード・長さは検査済み。語尾・異音・演技の最終判断はユーザーの再試聴待ち。表示台詞とシナリオは変更しない。

音声チェックを開くと、絞り込みを解除して未確認の音声だけを場面順で表示する。未判定の再生済み音声は含むが、判定済み（問題なし・指摘済み）・修正待ち・修正後の再確認対象は混ぜない。記録は削除しない。「絞り込み・検索」の隣の「修正後の確認」で、端末に指摘を記録した後に音声が差し替わった台詞だけを表示する。指摘のない音声、過去に音量調整しただけの音声、問題なしと判定した音声は含めない。同じ位置の「未確認へ戻る」で初回確認に戻る。問題なしを付けた音声はその場で一覧から外れる。「すべて」「問題なし」の絞り込みでは再表示できる。修正内容はマニフェストの `repairComment` から一覧に取り込み、修正後の確認時に台詞の下に表示する。

台詞は既存のゲームモジュールから抽出する。本文、画像、BGM、セーブ形式は変更しない。

全体生成・読み修正の前に `docs/voice-failures.md` と `config/voice-pronunciation-issues.json` を確認する。ドライランは要注意語の正しい読みと該当箇所を自動表示する。読み指定は生成入力のかな置換に適用し、表示本文は維持する。登録後も生成済みMP3は自動では変わらない。

1. `npm run voice:setup` をターミナルで実行し、非表示の入力欄にAPIキーを貼り付ける。
2. `npm run voice:verify` は Voice ID・日本語モデル・実残高をGETで確認する。音声は生成しない。
3. `npm run voice:plan` は通信なしのドライラン。話者・演技・文字数・設定・推定消費量は `.local/voice-plan.json` にも保存する。
4. ユーザーが指定した生成範囲の承認に従う。通常の見積もり報告・試作・再確認は不要（2026-10-18ユーザー指定）。消費量や対象件数に異常がある場合だけ生成前に確認する。計画ハッシュと見積もりは内部の安全確認用に保持する。
5. 承認後のみ `node tools/voices.mjs --generate --approve=<planId>` を実行する。現在の計画ハッシュが一致する場合のみ送信可能。第一幕のモク全体は `--scope=act1 --speaker=cat` を計画・生成の両方に指定する。第一幕の大家全体は `--scope=act1 --speaker=manager` を指定する。第二幕全体の無制限生成は許可しない。`--scope=act2-trouble1` は第二幕オープニング・入居会話・トラブル1までの観察会話・全選択肢・初回専用悲劇・巻き戻しを3人限定で生成する。男・ナレーション・トラブル2以降は除外する。
6. `npm run build` でマニフェストを反映する。生成MP3と `src/voice-manifest.js` を一緒に配布する。音声は発話時のみ読み込む。play.html単体を移動した場合もassets/voicesを隣に置く。

キーは `.local/elevenlabs.json` に平文でローカル保存される。共有PCではOSアカウントのアクセス権で保護する。`.local/` 全体はGit対象外で、ローカルHTTPサーバーも配信しない。公開ビルドにはソースJS・表示用アセットだけを含める。削除する場合はこのファイルを削除し、失効はElevenLabsのAPIキー管理画面で行う。キーをチャットやログに貼らない。

`--scope=act1 --speaker=cat` は第一幕のモクだけを抽出・生成する。選択肢の全分岐、エピローグ、周回と日常の移動・独り言を既存ゲームの状態遷移から抽出する。`--scope=act1`（話者指定なし）、`--scope=act2`、`--scope=all` は抽出確認専用で、一括生成は拒否する。将来の追加は同じextractorに幕のデータソースを登録する。

## 演技

Eleven v3の公式に対応する音声タグとvoice_settingsを使用する。設定は `config/voice-performance.json`。directionは人間向けの指示で、APIの自由文演技指示フィールドではない。本文は変更せず、生成要求のみにタグを前置する。通常・心の声・ツッコミは別設定と別キャッシュ。ツッコミを感嘆符や画像の怒り表情から分類しない。内省は既存のinnerVoiceフラグとプロローグの話者ラベルで判定する。

公式仕様: https://elevenlabs.io/docs/api-reference/text-to-speech/convert
音声タグ: https://elevenlabs.io/docs/help-center/product/core-capabilities/text-to-speech/how-do-audio-tags-work-with-eleven-v3-and-v4

モデル対応タグでも演技・発音は確率的で、読み上げられない保証はできない。生成後に試聴し、タグの発音・威圧的な演技・「ニャ」の発音を確認する。問題があれば設定修正で別キャッシュ候補にし、再生成の承認を得る。

クレジット推定は入力文字数（タグを含む）×設定単価であり、契約・モデルの実請求とは異なる可能性がある。実残高はGET /user/subscriptionから別表示する。生成前後の差分も同一アカウントの別用途の消費を含み得る。

## 再開

成功音声は毎回マニフェストに保存する。既存MP3を再利用し、自動再試行はしない。送信前に `.local/voice-journal.json` にintentを書き込む。失敗・中断の記録があるクリップは停止し、ElevenLabsの履歴で請求と生成物を照合する。取得済み音声を対応ハッシュのMP3へ復元すれば再利用できる。未生成と確認できた記録だけを手動解除する。ロックファイルは並列生成を拒否する。異常終了で残ったロックも、自分が起動した生成が終了済みと確認してから解除する。

ゲーム内は会話MENUでボイスON/OFF・音量を調整する。次へ・戻る・SKIP・画面終了で音声を停止し、AUTOは通常の表示待ち時間と再生終了の両方を待つ。未生成・読み込み失敗・自動再生拒否時は従来のテキスト進行を維持する。

## スマホ用の音声チェック

デバッグメニューの「音声チェック・指摘の出力」から開く。第一幕・第二幕の現行台本だけを抽出し、幕・場面・話者・確認状況・台詞検索で絞り込む。ゲームと同じ音声と話者別音量補正を使用する。連続再生は聞いた記録だけを付け、問題なしとは自動判定しない。指摘は複数選択でき、メモも入力途中から自動保存する。

保存キーはリリース番号から独立した `kemono-voice-review-v1`。通常のゲームセーブには書き込まない。識別キーはゲームの音声検索キーを共有し、音声版は実際に再生するMP3の内容ハッシュで判定する。更新しても確認記録を消さず、音声の内容が変わった分だけ再確認にする。削除・変更された旧台詞の指摘も出力・バックアップに残す。

「指摘を出力」からChatGPT / Codex向けの依頼をコピーまたは共有できる。バックアップJSONはファイル保存と読み込みに対応し、復元では新しい記録を優先して統合する。同じブラウザーのデータを削除した場合や端末を変える場合はバックアップから復元する。

カタログは `node tools/build-voice-review.mjs` で生成し、`npm run build` の前処理でも更新する。音声を差し替えたらビルドしてカタログと実音声の版を揃える。音声生成後は `ffprobe` で長さを検査し、まとまった文章が0.5秒未満の録音は採用しない。`--text=表示台詞` で修正対象1種類に絞れる。

2026-10-25の信号解析による修正は `config/voice-quality-repairs.json` の29本に限定。0.16秒だったモクの台詞は以前の正常な1.6秒の録音から復旧、27本は前後の余分な無音のみ短縮、奥義1本はピークを抑制した。再処理は `node tools/repair-audited-voices.mjs` と `node tools/build-attack-voices.mjs --refresh-quality`。台詞の中の演技の間や意図した沈黙は削らない。発音と演技の品質は信号解析の合格をもって保証しない。

### 音声チェックの更新・分類ルール

「確認状況」で修正音声・履歴あり、修正後OK、問題なし、新規、音声変更・再確認、削除された台詞を分けて絞り込める。問題なしには修正後OKも含む。並べ替えは場面順、新規・再確認を優先、指摘・確認の新しい順、キャラ順。

初めてこの版の音声チェックを開いたときに基準一覧を保存する。以降、追加された台詞は新規として表示し、文言変更は新しい台詞と旧台詞の削除履歴として扱う。旧台詞のOK判定を別の文言へ自動移植しない。音声だけが変更された場合は再確認にする。削除された台詞は通常の確認・再生対象から除外するが、チェック済みかどうかに関係なく一覧履歴に保持する。古い版で既に消えていた未記録の台詞は遡って復元できない。基準一覧がない旧版のデータでも、残っている指摘やメモは引き継ぐ。

修正履歴の判定には明示された修正音声と、利用者の記録・保存した一覧との音声版比較を使う。修正後の音声を問題なしと確認したものは修正後OKになる。削除済みの指摘を出力する場合は履歴であることと再生成不要を明示する。基準一覧も従来と同じ保存キー・バックアップ形式に追加して保持し、通常のゲーム更新では初期化しない。
